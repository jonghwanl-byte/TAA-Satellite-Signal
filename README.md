# TAA-Satalite-Signal

국내 상장 ETF(연금계좌)용 **범용 이동평균 추세 신호**. 매일 아침 GitHub Actions가 신호를 계산해 텔레그램으로 보낸다.

- 대상: 069500 KODEX200 · 283580 KODEX 중국본토CSI300 · 241180 TIGER 니케이225 · 453810 KODEX 인도Nifty50 · 385560 KBSTAR KIS국고채30년
- 자산별 한도 20%, 현금 포함 나머지는 수동 관리
- 같은 규칙을 모든 자산에 똑같이 적용한다 (자산별 튜닝 없음)

## 1. 매매 규칙

| 항목 | 내용 |
|---|---|
| 판정 단위 | 일봉 종가, 이평선 20/60/120/200일 (4개) |
| 밴드 | 종가 > MA×1.02 → ON, 종가 < MA×0.98 → OFF, 그 사이는 전일 상태 유지 |
| 목표 비중 | (켜진 이평선 수 ÷ 4) × 20% → 0 / 5 / 10 / 15 / 20% |
| 주봉 | 20/60주선 ON/OFF를 **참고 표시**만 한다 (비중에 반영 안 함) |
| 고점/저점 대비 | 120일 안전장치 등은 **쓰지 않는다** (아래 3번). 메시지에는 참고 수치로만 표시 |
| 집행 | 신호는 당일 종가 기준, **다음 거래일 종가 무렵(14시경)** 매매 |

한 날에 비중이 바뀌면 그 차이만큼만 사고판다. 비중이 같으면 매매하지 않는다.

## 3. 판단 근거 요약

1. **이 규칙은 수익보다 MDD를 줄이는 규칙이다.** 코스피·니케이·중국은 CAGR이 Buy&Hold보다 낮고 MDD는 줄었다. 칼마가 뚜렷이 좋아진 것은 국고채30년이고, 합산에서는 개선되지만 표본이 2.7년뿐이다.
2. **고점 대비 -12% 하락 시 비중 50% 상한(저점 +5% 반등 시 해제)은 효과가 없었다.** 고점 대비 -12%일 때는 이평선 대부분이 이미 OFF라서 기본 비중이 50% 이하이고, 상한이 걸릴 일이 거의 없다. 창(20/60/120/200일), 하락폭, 반등폭을 바꿔 봐도 일관된 개선이 없어서 규칙에서 뺐다.
3. **코스피200의 큰 낙폭(-38%)은 급락이 아니라 2011~2016년 박스권 휩쏘 때문이다.** 하락 안전장치로는 막을 수 없다. 자산별 한도 20%로 계좌 영향이 제한된다.
4. **매매가 잦다.** 5자산 합산 약 연 360% 회전. 비용 0.3% 가정 시 수익이 줄어드니, 5%p 단위 비중 변화는 소액이면 합쳐서 매매해도 된다.

## 4. 한계와 주의

- **짧은 표본**: 인도 2.7년, 국고채 4.6년, 중국 8년, 일본 9.8년. 결과를 확정 성능으로 보면 안 된다.
- **가격 기준 혼재**: 사용한 CSV는 조정가와 무조정가가 섞여 있다. 배당 반영 여부에 따라 수익이 조금씩 달라지고, 분배금이 큰 국고채에서 영향이 크다. 운영 코드는 pykrx(무조정 종가) → 네이버(무조정) → yfinance(조정) 순서로 가장 긴 히스토리를 쓴다. 소스가 바뀌면 신호가 어긋날 수 있어 로그의 "채택 소스"를 확인한다.
- **히스테리시스는 경로 의존적**이다. 히스토리가 짧으면 초기 상태가 실제와 달라지므로 2005년부터 전체를 받아 계산한다.
- 시가 체결 시나리오와 비용 0.3% 민감도는 큰 차이가 없었다 (합산 CAGR 약 -1.5%p).

## 5. 텔레그램 메시지 보는 법

```
📊 TAA Satellite 신호 (밴드 ±2%)

KODEX 인도Nifty50 (453810) 11/13
일 ●●○○  주 ●○  전일대비 ▼0.7%
목표 10% (한도 20% 중)  변동없음
⚠ 전환 임박: 일120   ← 전환선 0.5%p 이내일 때만 표시
━━━━━━━━━━
📋 상세 (고점대비 / 저점대비 / MA대비)
```

- `●` ON, `○` OFF, `-` 데이터 부족. 순서는 일 20/60/120/200, 주 20/60.
- 목표 줄에 `▲ 비중확대 10%→20%` 또는 `▼ 비중축소`가 나오면 그날 매매한다.
- 상세의 고점/저점 대비는 참고용이다. 매매 판단은 상단 신호로만 한다.
- `PORTFOLIO_VALUE`를 설정하면 목표 금액과 수량도 표시한다.

## 6. 설치

### 6-1. GitHub

1. 이 폴더를 새 저장소 `TAA-Satalite-Signal`로 올린다. 기존 P모델/위성 저장소와 **분리**해야 알림이 중복되지 않는다.
2. 저장소 Settings → Secrets and variables → Actions
   - Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (필수), `PORTFOLIO_VALUE` (선택, 숫자만)
   - Variables(선택): `ALWAYS_SEND` (`false`면 변동·전환 임박·오류일 때만 전송), `PRICE_SOURCE` (예: `naver,pykrx`)
3. Actions 탭에서 `TAA Satellite Signal`을 수동 실행(Run workflow)해 메시지가 오는지 확인한다.

### 6-2. cron-job.org (매일 06:30 KST)

- 시간대 `Asia/Seoul`, 시각 06:30, 요일 월~금 (한국장 종가 기준이라 토요일 실행은 금요일 신호와 같다)
- URL: `https://api.github.com/repos/<계정>/TAA-Satalite-Signal/actions/workflows/signal.yml/dispatches`
- Method `POST`, Body `{"ref":"main"}`
- Headers
  - `Accept: application/vnd.github+json`
  - `Authorization: Bearer <토큰>` (Fine-grained PAT, 이 저장소의 Actions: Read and write 권한만)
  - `X-GitHub-Api-Version: 2022-11-28`
  - `Content-Type: application/json`
- 성공 응답은 HTTP 204.

### 6-3. 로컬 테스트 (Windows)

```
pip install -r requirements.txt
set DRY_RUN=true
python taa_signal.py
```

CSV로 테스트하려면 `{코드}.csv`(Date, Close 열)가 든 폴더를 `CSV_DIR`로 지정한다.
